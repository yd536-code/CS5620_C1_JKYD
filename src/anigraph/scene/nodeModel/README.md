# Node Model

`ANodeModel` (extends `AModel` from [../../base/amvc/](../../base/amvc/README.md)) is the abstract root every scene-graph node's data class derives from: it carries a transform, a geometry set, a material, visibility, render order, and tag support, and fires typed events (`GEOMETRY_UPDATE`, `TRANSFORM_UPDATE`, `RENDER_ORDER_UPDATE`) when those change so a node view (see [../nodeView/](../nodeView/README.md)) can react without polling. (`TEXTURE_UPDATE` and `COLOR_UPDATE` are also defined, but nothing in AniGraph signals them.) `ANodeModel2D`/`ANodeModel3D` specialize it per-dimension — 2D models store a `Mat3`/`NodeTransform2D` transform and a `VertexArray2D`, 3D models a `NodeTransform3D`/`Mat4` and a `VertexArray3D`. Both implement `ANodeModel.embedTransform(transform): Mat4`, which is how a view turns a node's transform into the 4x4 matrix it applies to its render object without needing to know whether the node is 2D or 3D (see [../nodeView/](../nodeView/README.md)).

A node's transform representation (`NodeTransform2D` versus `Mat3` in 2D, `NodeTransform3D` versus `Mat4` in 3D) is runtime state, not a class choice: `setTransformToIdentity()` defaults every node to PRSA (position/rotation/scale/anchor, since it animates per component).

**Editing a transform: `node.prsa`.** `prsa` is the node's *live* PRSA transform, and editing it edits the node. It throws on a matrix node rather than hand back a copy whose edits would be lost; `transformIsPRSA` tells you which you have. `convertTransformToPRSA()`/`convertTransformToMatrix()` convert in place (a no-op on their own type). `setTransform(t)` **keeps the node's current representation**: a matrix given to a PRSA node is decomposed (`NodeTransform2D/3D.TryFromMatrix`), keeping the node's anchor, and a PRSA given to a matrix node is stored as its matrix. Before any transform exists (in the constructor), `t` is stored as given, so a node constructed with a `Mat3` holds a `Mat3`. It warns once per node, in development builds, in two cases: a matrix with shear given to a PRSA node (the node then switches to that matrix), and a non-zero anchor folded into a matrix. A 3D node's `setTransform` rejects a `Mat3` or `NodeTransform2D`. The old names are deprecated aliases: `getTransformAsPRSA()` (always returns a copy), `setTransformToMatrix()`/`setTransformToPRSA()` (2D) and `setTransformToMat4()` (3D). `setTransformPRSA(t)`/`setTransformMat3(t)` (2D) still set and change the representation on purpose. Code that must change the representation assigns `_transform` directly, since the protected `transform` setter goes through `setTransform`. A subclass that wants its own default overrides `setTransformToIdentity()`; no per-representation subclass exists in the framework itself. `AGroupNodeModel2D`/`AGroupNodeModel3D` are node models with no geometry of their own, used purely to group and transform a set of child nodes together.

A node can animate itself with `addTimedAction(callback, duration, onDone?, tween?, handle?)`, which runs on its scene's clock (`sceneClock`, the `clock` of the scene model that holds the node's model graph) and is stored as a subscription on the node, so releasing the node stops it and `unsubscribe(handle)` cancels it. It shares its implementation with `ASceneModel.addTimedAction` and `AController.addTimedAction` (`AClock.addTimedActionTo`, in [../../time/](../../time/README.md)). The node must already be in a scene; calling it on a detached node throws.

**Transform updates.** `autoTransformUpdate` (true by default) picks one of two strategies for keeping a node's views in sync with its transform. With it on, every change under `transformStateKeys` (`_transform`, plus `_zValue` for 2D nodes; nested edits such as `prsa.position.x = ...` included) signals `TRANSFORM_UPDATE` right away, passing `automatic = true` as the event's second argument. With it off, transform edits signal nothing until `signalTransformUpdate()` is called, so a node whose transform changes many times in a frame redraws once. `flushTransformUpdate()` signals only when it's off, for code that should work either way; turning it back on signals once. Views receive the event in `onTransformUpdate()` (see [../nodeView/](../nodeView/README.md)); their general state listener ignores the transform keys. Note: one edit can produce more than one event (e.g. `position.x = 3` is two valtio ops, the `x` setter and the element it writes).

## Contents:
- [./AGroupNodeModel2D.ts](./AGroupNodeModel2D.ts): 2D group node model — a container node with a 2D transform used to group child nodes.
- [./AGroupNodeModel3D.ts](./AGroupNodeModel3D.ts): 3D group node model for organizing child nodes under a shared 3D transform.
- [./ANodeModel.ts](./ANodeModel.ts): Abstract base for all scene graph node models. Carries a transform, geometry set, material, visibility, render order, and tag support. Fires typed events for geometry, transform, and render-order changes. Has `addTimedAction`/`sceneClock` for animations on the scene's clock (see above). Declares the abstract `embedTransform(transform): Mat4` every subclass implements (see above), plus `getInstanceControlSpecGroup()`/`static getClassControlSpecGroup()`, each returning an [`AControlSpecGroup`](../../controlpanel/README.md) (or `undefined`, the default) so a subclass can expose its own control-panel controls polymorphically instead of a scene hand-writing an `instanceof` chain — see `../../appstate/ControlPanel.md`'s "Letting a model expose its own controls".
- [./ANodeModel2D.ts](./ANodeModel2D.ts): 2D node model with a `Mat3` or `NodeTransform2D` transform (defaulting to `NodeTransform2D`; see above) and a `VertexArray2D`. `zValue` (draw order) is stored in the `@AObjectState` field `_zValue`, which is one of its `transformStateKeys`, so a `zValue` change is a transform change. Implements `HasBounds2D`.
- [./ANodeModel3D.ts](./ANodeModel3D.ts): 3D node model with a `NodeTransform3D`/`Mat4` transform and a `VertexArray3D`. Implements `HasBounds`.
- [./NodeModelSubclass.ts](./NodeModelSubclass.ts): Generic abstract subclass bridging `ANodeModel` with typed transform and vertex array parameters.
- [./index.ts](./index.ts): Barrel export for the nodeModel module.

---

### Key properties
- `model.transform`: The model matrix for the scene graph node (Mat3 or NodeTransform2D in 2D, Mat4 or NodeTransform3D in 3D).
- `model.geometry` (`AGeometrySet`): Container for geometry; `model.verts` accesses the primary vertex array.
- `model.material` (`AMaterial`): Material used to render the node.
