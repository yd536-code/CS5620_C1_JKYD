# Camera

`ACameraModel3D` (extends `ANodeModel3D`, so a camera is itself a scene node like any other) holds its pose as its own node transform -- `getWorldTransform()`/`getRenderMatrix()`/`getWorldRenderMatrix()` all work normally, so a camera parented under another node (or another camera) follows its parent's pose. It also wraps an `ACamera` from [../../math/camera/](../../math/camera/README.md), which holds the projection and does the pose-dependent math (`PV`, `forward`/`right`/`up`, `viewMatrix`) that `ACameraModel3D` does not reimplement. The node's transform and the wrapped camera's pose are kept in sync in both directions, and after a sync they are the same object (`cameraModel.transform === camera.pose`): replacing the node's transform (`setTransform`, `setPose`, `setPosition`) sets the camera's pose, and replacing the camera's pose (`camera.setPose(...)`) sets the node's transform. Both directions are needed because some scenes and interaction modes move the camera through the wrapped `ACamera` rather than through the node. An in-place edit (for example `cameraModel.prsa.position = ...`) changes both right away, but listeners added with `camera.addPoseListener` only hear about a pose that is *replaced*; see the class docs in `ACameraModel3D.ts`. `ACameraView` is the Three.js counterpart: it renders the *local* matrix into `.matrix` and the *world* one (composed through the model-graph parent chain) into `.matrixWorld`/`matrixWorldInverse`, and listens for the model's projection changes to keep the Three.js camera's projection matrix current.

`ACameraModel2D` (extends `ANodeModel2D`) is the 2D camera, created by `ASceneModel2D`'s orthographic camera setup and panned and zoomed by `PanZoomController2D` (see [../../starter/interactionmodes/cameracontrollers/](../../starter/interactionmodes/cameracontrollers/README.md)). Its pose is its own 2D node transform. Its wrapped `ACamera` is used only for projection (frustum, `zoom`, resizing): the `ACamera`'s pose is 3D, is not connected to the node, and stays at its default, so `forward`/`right`/`up` describe that default pose, not the node's. `ACameraModel2D.ndcToWorld` uses the node's world transform (embedded as a `Mat4` by `getWorldRenderMatrix()`), so cursor-to-world conversion (`ASceneController.getWorldCoordinatesOfCursorEvent`) follows the camera's pan and zoom; `ACameraModel3D.ndcToWorld` does the same with its world transform, so it also works for a parented camera. `ACameraView` renders both kinds of camera, since it only uses members they share.

Both classes share their dimension-agnostic members (`camera`, `projection`, `onCanvasResize`, `ndcToWorld`, `forward`/`right`/`up`, projection-change listeners) through `WithCamera.ts`'s `CameraModelInterface`, which `applyWithCamera` copies onto each class's prototype rather than using a class mixin (see that file for why). `ASceneModel.cameraModel` (an accessor pair over the protected `_cameraModel` field) is typed to `CameraModelInterface & ANodeModel`, not to either concrete class, so either can fill it. `ASceneModel2D` and `ASceneModel3D` override the accessors to narrow the type to `ACameraModel2D` and `ACameraModel3D`, so scene code can use the concrete camera (for example `this.cameraModel.prsa`) without a cast. `addCameraChangeListener` uses a whole-object state listener, so it fires on in-place pose edits (as `PanZoomController2D` makes) as well as on projection updates.

**Parented cameras.** A camera model can be parented under another (for example, one `ACameraModel3D` under another, so the second camera inherits the main camera's pose). This has only been used with a parent whose pose is set once and never changes, so it has not been checked whether a *moving* parent updates a child camera's rendered `.matrixWorld` every frame without the child view updating itself. Test a moving parent-child camera rig before relying on it.

## Contents:
- [./__tests__/](./__tests__/README.md): Tests for the 2D and 3D camera models and `ACameraView`.
- [./ACameraModel2D.ts](./ACameraModel2D.ts): 2D node model wrapping an `ACamera` for projection only; its pose is its own 2D transform. Created by `ASceneModel2D`'s orthographic camera setup and moved by `PanZoomController2D`. Its `ndcToWorld` uses the node's own world transform.
- [./ACameraModel3D.ts](./ACameraModel3D.ts): 3D node model whose pose is its own node transform, kept in sync (both ways) with a wrapped `ACamera` used for projection and pose-dependent queries. Exposes `pose`, `projection`, `setPose`, `setPosition`, `ndcToWorld` (uses the world transform), and resize callbacks.
- [./ACameraView.ts](./ACameraView.ts): Node view that wraps a Three.js `THREE.Camera`. Renders the model's local transform into `.matrix` and its world transform into `.matrixWorld`, and listens for projection changes.
- [./WithCamera.ts](./WithCamera.ts): `CameraModelInterface` (the shared camera members) and `applyWithCamera` (copies their implementation onto a camera class's prototype -- see the file for why this isn't a class mixin). `addCameraChangeListener` fires on any state change of the camera model, including in-place pose edits, and on projection updates.
- [./index.ts](./index.ts): Barrel export for the camera module.
