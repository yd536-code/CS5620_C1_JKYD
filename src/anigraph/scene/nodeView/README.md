# Node View

Node view base classes for scene graph rendering — the other half of the model/view split from [../nodeModel/](../nodeModel/README.md). `ANodeView` (extends `AView` from [../../base/amvc/](../../base/amvc/README.md)) is the backend-agnostic base: it subscribes to a model's state/transform/geometry/visibility/render-order/parent-change events (the `BASIC_VIEW_SUBSCRIPTIONS` handles) so a view stays in sync without polling (any state change other than the transform's calls `update()`; transform changes arrive as `TRANSFORM_UPDATE` events and call `onTransformUpdate()`, which defaults to `update()` and is `updateTransform()` for Two.js views, so a model with `autoTransformUpdate` off can batch them — see `nodeModel/README.md`), manages the set of registered graphic objects that make up its render output, and declares the abstract hooks (`_initRenderObject`, `addToParentView`, `updateTransform`, `isAttachedToRenderHierarchy`) that a backend must implement to actually create and place a render object in that backend's scene graph. `AGLNodeView` is the Three.js implementation of those hooks (holding a `THREE.Object3D`, managing loaded elements, and handling material-update events) — scene authors normally subclass `AGLNodeView` (or, for Two.js scenes, `ATwoJSNodeView` in [../../rendering/twojs/](../../rendering/twojs/README.md)) and implement `init()`/`update()`, rather than implementing `ANodeView`'s abstract hooks directly. `AGroupNodeView` is a minimal concrete view that just propagates its model's transform to the backend render object each frame, used by both group node models in `nodeModel/`. A view never inspects whether a transform is 2D or 3D: `AGLNodeView.setTransform`/`updateTransform` ask the model to embed the transform (`ANodeModel.embedTransform`/`getRenderMatrix`), so the same view code serves 2D and 3D nodes. `AMeshView` is the shared base for views that draw a model's vertices as a triangle mesh.

## Contents:
- [./ANodeView.ts](./ANodeView.ts): Backend-agnostic abstract node view. Manages registered graphic objects, subscribes to model state/transform/geometry events, and defines the abstract render-object hooks (`_initRenderObject`, `addToParentView`, `updateTransform`) that backends implement. (If you have older code that did `extends ANodeView` for a Three.js view, change it to `extends AGLNodeView` — see MIGRATION.md.)
- [./AGLNodeView.ts](./AGLNodeView.ts): Three.js node view base. Holds the view's `THREE.Object3D`, manages loaded elements, and provides material update/change event handling.
- [./AGroupNodeView.ts](./AGroupNodeView.ts): Group node view for 2D and 3D group models. Propagates the model's transform to the Three.js object each frame.
- [./AMeshView.ts](./AMeshView.ts): Shared base for views that draw a model's 2D or 3D vertex array with an `ATriangleMeshGraphic` (`A2DMeshView`, `ATriangleMeshView`, `RGBATestMeshView`). Whether `update()` re-sends the vertices is an explicit per-subclass choice.
- [./index.ts](./index.ts): Barrel export for the nodeView module.
