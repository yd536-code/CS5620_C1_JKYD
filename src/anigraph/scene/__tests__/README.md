# __tests__

Jest specs for the [scene](../README.md) module. `AModelGraph.test.js` checks [`AModelGraph`](../AModelGraph.ts), the root of a scene's model hierarchy: the core bookkeeping a scene graph depends on: that `addNode` registers a node under its `uid` in `modelMap`, that adding the same node twice doesn't create a duplicate entry, that `SceneGraphEvents.NodeAdded`/`NodeRemoved` fire with the affected node's `uid` when nodes are added/removed via `removeChild`. These are the low-level guarantees the rest of [../](../README.md) (scene views mapping models to node views, controllers tracking scene contents) relies on implicitly.

`RenderMatrix.test.ts` and `NodeViews.test.ts` cover how a node reaches the Three.js renderer. The first keeps a reference copy of the view-side 2D transform logic and asserts that the model-side embedding (`embedTransform`, `getRenderMatrix`, `getWorldRenderMatrix`) produces identical 4x4 matrices for 2D and 3D nodes. The second checks the views built on it: group views for 2D and 3D nodes, a view following a later `zValue` change, world-transform and already-embedded matrices, the loud failure for a 2D transform on a 3D node, and the vertex-update policy that distinguishes the 2D and 3D mesh views.

`ARenderPass.test.ts` covers `../ARenderPass.ts`: its viewport math against a reference copy of hand-written split-screen viewports, and `render()`'s exact call sequence (viewport, scissor, render target, clear, `renderer.render`) against a minimal mock context/controller -- including a two-pass test that shows why the scissor rectangle is needed: `WebGLRenderer.clear()` clears the whole framebuffer, not just the current viewport, so without a matching scissor rect a second pass's clear erases the first pass's pixels outside its own viewport. It also covers `findPassAtCursor` (front-to-back pass hit-testing against fake passes, including the `interactive`/`visible` skip rules) and `worldPointAtCursor` (that a pass routes to its *own* camera and its *own* re-normalized NDC, not the canvas-global one).

`TransformUpdateStrategies.test.ts` checks how transform changes reach views: with `autoTransformUpdate` on (the default), every transform edit, nested ones included, redraws right away; with it off, edits wait for one `signalTransformUpdate()`. Views count their `update()`/`onTransformUpdate()` calls by wrapping them.

`NodeSpaceCompatibility.test.ts` is the integration test, against the real `ANodeModel2D`/`ANodeModel3D`/`PolygonModel2D` classes, for `AObjectNode._addChild`'s space check (`../../base/aobject/__tests__/AObjectNode.test.js` tests the generic mechanism in isolation with lightweight fakes): the classes report the right `nodeSpace` tag, mixing is rejected at `addChild` time in both directions, and same-space parenting plus `getWorldTransform()` still work with no `instanceof` guard in the call path.

## Contents:
- [./AModelGraph.test.js](./AModelGraph.test.js): Tests `AModelGraph` node addition/removal and the events it fires.
- [./ARenderPass.test.ts](./ARenderPass.test.ts): Viewport-math, `render()` call-sequence, `findPassAtCursor`, and `worldPointAtCursor` tests for `ARenderPass`.
- [./ASceneController.test.ts](./ASceneController.test.ts): Tests the two members `ASceneController` implements for both backends: `getWorldCoordinatesOfCursorEvent` and `initSceneViews`.
- [./ASceneModel.test.ts](./ASceneModel.test.ts): Tests `ASceneModel`'s typed node queries (`getNodesOfType`, `getNodeModelsForModelGraph` with a graph object or name) and node-event binding.
- [./ASceneView.test.ts](./ASceneView.test.ts): Tests the model/view bookkeeping and class registry `ASceneView` implements for both backends (`hasModel`, `hasView`, `addView`, `getViewListForModel`, `disposeViews`, `release()`, `addModelViewSpec`/`defaultViewClass`), including `onModelNodeReleased` calling `.release()`, not just `.dispose()`, on every view.
- [./NodeTags.test.ts](./NodeTags.test.ts): Tests node tags (`addTag`, `setTagValue`, `hasTag`, `getTagValue`, `removeTag`), `ASceneModel.getNodesWithTag` with and without a value (including nested nodes and a value of `false`), and that tags survive a save/load round trip.
- [./NodeTimedAction.test.ts](./NodeTimedAction.test.ts): Tests `ANodeModel.addTimedAction` and `sceneClock` against a real scene model's clock: progress values, the final call with exactly the final progress, the tween, the error for a detached node, handle dedupe, canceling with `unsubscribe`, and that releasing the node stops the action. Also checks `ASceneModel.addTimedAction`, which shares the implementation.
- [./NodeSpaceCompatibility.test.ts](./NodeSpaceCompatibility.test.ts): Integration test, against the real `ANodeModel2D`/`ANodeModel3D`/`PolygonModel2D` classes, for the 2D/3D space check on `addChild`.
- [./SubtreeAddRelease.test.ts](./SubtreeAddRelease.test.ts): Tests adding a subtree that was built before it joined the graph (every node registered, `NodeAdded` in preorder, one view per node nested under its parent's view, on both the Three.js and Two.js scene views) and releasing a subtree after it was detached (every node leaves `modelMap`, `NodeReleased` fires exactly once per node, views are released, a reused `uid` gets a new view, and `bindNodeEvent` binds and unbinds subtree nodes). Also tests reparenting within the scene.
- [./RenderMatrix.test.ts](./RenderMatrix.test.ts): Checks the model-side render-matrix embedding against a reference copy of the view-side logic.
- [./AsyncInitScene.test.ts](./AsyncInitScene.test.ts): Checks that initialization waits for an async `initScene`: the scene model isn't initialized, and its clock doesn't start, until `initScene` finishes; the scene controller's `confirmInitialized` promise resolves only after the model, views and rendering are set up.
- [./ANodeModel2D.test.ts](./ANodeModel2D.test.ts): Tests `ANodeModel2D`'s transform representation: new 2D nodes default to `NodeTransform2D`, an explicit `Mat3` is kept, `getTransformAsPRSA` returns a copy, the deprecated `setTransformToMatrix`/`setTransformToPRSA` aliases convert in place, and `setTransformPRSA`/`setTransformMat3` change the representation on purpose.
- [./ANodeModel3D.test.ts](./ANodeModel3D.test.ts): Checks that the `ANodeModel3D` constructor keeps the vertices it is given, and defaults to an empty `VertexArray3D`.
- [./NodeViews.test.ts](./NodeViews.test.ts): Tests for the Three.js group, mesh and 2D line views' transform application and vertex-update policies.
- [./TransformRepresentation.test.ts](./TransformRepresentation.test.ts): Tests editing a transform: `prsa` (live on PRSA, throws on a matrix), `transformIsPRSA`, `convertTransformToPRSA()`/`convertTransformToMatrix()`, `setTransform` keeping the representation (decomposing a matrix and keeping the anchor, warning once for shear or a lost anchor), the deprecated aliases, `adopt()` (reparenting a node without moving it on screen), and the 3D versions, including `setTransform(Mat3)` throwing.
- [./TransformUpdateStrategies.test.ts](./TransformUpdateStrategies.test.ts): Tests the two transform-update strategies (`autoTransformUpdate` on: nested edits and `zValue` redraw right away; off: edits wait for `signalTransformUpdate()`/`flushTransformUpdate()`), that other state changes still reach the view, the Two.js views' `updateTransform()`-only path, and `ACameraModel3D`'s pose sync.
- [./AGLSceneController.test.ts](./AGLSceneController.test.ts): Checks that `setCurrentRenderTarget` records the target, and resets `currentRenderTarget` to `null` when switching back to the canvas.
- [./QuickNodeView.test.ts](./QuickNodeView.test.ts): Checks that a `QuickNodeView` with missing `init`/`update`/`dispose` callbacks can still run those methods, and that given callbacks are called with the view.
