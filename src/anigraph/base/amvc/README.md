# AMVC

This directory defines the abstract, backend-agnostic Model/View/Controller triad that every concrete node type, scene, and starter app specializes — the shared vocabulary that lets the same scene-graph logic work with both the Three.js and Two.js rendering backends. `AModel` extends [`AObjectNode`](../aobject/README.md) with essentially nothing beyond firing a `RELEASE` event on disposal — models are otherwise just reactive tree nodes with whatever state a subclass adds (see [../../scene/nodeModel/](../../scene/nodeModel/README.md)). `AView` is intentionally thin too: it only holds a `controller` reference and an abstract `modelID`; the actual backend render object (a `THREE.Object3D` or a Two.js group) is added by a concrete subclass like `AGLNodeView`, not by this base class, which is what keeps view code backend-agnostic at this layer. `AController` is the most substantial class here — it owns an `AClock` for timed actions, an `AInteractionModeMap` (see [../../interaction/](../../interaction/README.md)) for switching between named interaction modes, and `addTimedAction` for running a callback over a duration with an optional easing tween; `AController` also defines the `SceneControllerInterface` that concrete Three.js/Two.js scene controllers implement. `AModelViewClassSpec.ts` and `AModelViewMap.ts` supply the glue types (`AMVClassSpec`, `AModelViewClassMap`, `HasModelMap`/`HasModelViewMap`) that let a scene view look up which view class to instantiate for a given model class, and `HasInteractions` is the interface `AController` implements for defining/activating/clearing interaction modes.

## Contents:
- [./AController.ts](./AController.ts): Abstract base controller class. Holds a reference to a model and a clock, manages an `AInteractionModeMap`, and defines the `SceneControllerInterface` for scene-level controllers.
- [./AModel.ts](./AModel.ts): Abstract base model class extending `AObjectNode`. Defines `AModelInterface` and emits a `RELEASE` event when disposed.
- [./AModelViewClassSpec.ts](./AModelViewClassSpec.ts): Types and interfaces for specifying which view class to use for a given model class (`AMVClassSpec`, `AModelViewClassMap`).
- [./AModelViewMap.ts](./AModelViewMap.ts): Interfaces `HasModelMap` and `HasModelViewMap` describing objects that maintain dictionaries of models and their associated views.
- [./AView.ts](./AView.ts): Abstract base view class. Backend-agnostic: holds a controller reference and manages subscriptions; backend-specific render objects live on subclasses (e.g. `AGLNodeView._threejs`, `ATwoJSNodeView._twoGroup`).
- [./HasInteractions.ts](./HasInteractions.ts): Interface describing objects that can manage interaction modes — defining, activating, clearing, and switching modes.
- [./index.ts](./index.ts): Barrel export for the amvc module.
