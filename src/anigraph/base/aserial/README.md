# ASerial

This module is what lets an AniGraph object be turned into JSON and reconstructed as the correct class later, rather than a generic object. New to this module? Start with [GUIDE.md](./GUIDE.md) instead — it's the same material in start-to-end onboarding order; this README is the per-symbol reference.

`@ASerializable(name)` is a class decorator — applied to every class whose instances a save file actually contains (models, `AObject`/`AObjectNode`, math value types, geometry, materials/textures) — that registers the class in a module-level `ASerializableClassesDict` keyed by name (falling back to the class's own name), stamps an `ASerializationClassID` onto the constructor, and (in non-production builds) warns if the class can neither be constructed with zero arguments nor provides a static `fromJSON` (see the construction-contract gotcha below). A name that's already registered under an *identical* class definition (`Function.prototype.toString()` matches — the ordinary HMR edit-save-reload case) just replaces that registration in place, with no warning. A name collision between two genuinely *different* classes registers the second one under the name plus a numeric suffix and logs a `console.warn` (dev-only). `AUnregisterSerializable(name)` removes a registration explicitly.

`@ALabel(name)` is the label-only counterpart: it sets the same `_serializationLabel` static that `@ASerializable` does, but does **not** register the class or run the construction-contract check. Use it on runtime-only classes — views, controllers, interaction modes, graphic objects, render contexts/windows/targets, material/shader models, managers, clocks. A scene is saved as its model hierarchy, and views are rebuilt from the Model View Specs on load, so none of those are ever revived from a save file. `GetClassLabel(ctor, warnIfMissing?)` reads a class's label: its *own* `@ALabel`/`@ASerializable` label, else its own class name — never an ancestor's. (Reading the static directly would find an ancestor's label through the prototype chain, so undecorated interaction modes would all be named `"ASceneInteractionMode"` and overwrite each other in the mode map.) Every `serializationLabel` getter goes through it. With `warnIfMissing` (used for interaction modes) it logs a one-time dev-only `console.info` when falling back to the class name. The production build keeps class names (`craco.config.js`), so the fallback is safe after minification too; `@ALabel` is only strictly needed when the label should differ from the class name.

`GetIndexedCopy(obj)` walks `obj` into a plain, JSON-safe structure. For any nested value whose constructor has that stamped class ID **as its own property, not inherited from a decorated ancestor** (see `hasOwnSerializationClassID` — an undecorated subclass of a decorated class must never be misidentified as the ancestor), it assigns that instance a short id the *first* time it's encountered and wraps it as `{_aserial_class_id, _aserial_id, _aserial_version?, data}`; encountering the *same* instance again anywhere else in the graph — a genuine shared reference, or a true reference cycle, no distinction needed — emits `{_aserial_ref: id}` instead of walking it again. `ASerializableToJSON(obj)` is just `JSON.stringify(GetIndexedCopy(obj), null, " ")`.

`ASerializableFromJSON(jsonText)` is a plain `JSON.parse(jsonText)` followed by a hand-written recursive revival walk (`ReviveNode`), not a `JSON.parse(text, reviver)` one-liner — see the gotcha below for why. On a `{_aserial_class_id, ...}` node it looks the class up via `GetASerializableClassByName`, constructs a **shell** instance and registers it (by `_aserial_id`) in a revival-scoped `Map` *before* recursing into `data`, runs the class's static `migrate(oldVersion, data)` if present and the saved `_aserial_version` is older than the class's current one, then either calls the class's static `fromJSON(data)` (the common case — every `AObject`/`AObjectNode` subclass has one, inherited) or falls back to `Object.assign`-ing onto the shell. A `{_aserial_ref: id}` node just looks itself up in that same map.

`@ASerializableField` is a separate, opt-in *field* decorator (not to be confused with `@AObjectState`/`@AObjectStateRef` in `../aobject`, which are about reactivity, not persistence): it marks a plain instance field for inclusion in `AObject.toJSON()`'s output without requiring the field to live in the reactive `state` proxy. Most real model classes keep their actual data in ordinary fields rather than `@AObjectState` — `@ASerializableField` lets those fields be saved without moving them into `state`. See the doc comment on `ASerializableField` in `ASerializable.ts` for a usage example. `GetOwnDecoratorArray` is the shared helper both this and `@AObjectState` use to track their per-class tagged-field lists with correct inheritance (a class's own list is a copy of whatever it inherited, extended with its own fields) — pushing directly onto whatever list the prototype chain resolves to would add a subclass's fields to its parent class too.

`AObject.AObjectVersion` (a plain static number, inherited default `1`) is the schema-version mechanism: `GetIndexedCopy` writes it into a wrapper as `_aserial_version` when a class has one, and omits the field entirely for a decorated class that's never touched versioning (most non-`AObject` value types today). A class that restructures its own saved shape bumps this as an *own* static field (`static AObjectVersion = 2;` — ordinary JS shadowing, safe without any `GetOwnDecoratorArray`-style trick since it's a scalar, not an accumulated list) and implements `static migrate(oldVersion, data)` to translate old data forward; a save file with no `_aserial_version` at all (an older save, or an unversioned class) is treated as version 0, never rejected.

`GETSERIALIZABLES()` returns the registry for inspection. `ValidateSerializableGraph(obj)` walks `obj` the same way `GetIndexedCopy` would — same decorated-instance detection, same identity-based dedup — but only inspects, never serializes, and returns an array of `{path, classId?, message}` issues instead of throwing or silently mis-saving. It answers "what would break if I tried to save this object graph right now" without actually trying it: a decorated instance that violates the construction contract (with the same false positives as the decoration-time check -- see the gotcha below), a nested object that looks like a real class instance but has no own `@ASerializable` decoration (silent data loss on save, see the `Date` gotcha below), and a reference cycle running purely through plain (undecorated) objects (the one case `GetIndexedCopy` has no protection for at all and would recurse forever on).

## Gotchas

**A decorated class with no custom `toJSON()` must not be handed its own still-decorated self on the next recursive step**, or the walk re-wraps it forever. `GetIndexedCopy` falls back to a shallow own-property copy (`{ ...inObject }`, matching plain `JSON.stringify`'s default behavior for a class instance) when `typeof inObject.toJSON !== "function"`. Writing a new decorated class doesn't require a `toJSON()` for this reason; the fallback is a *shallow* one-level copy of own enumerable properties, not `AObject.toJSON()`'s `@ASerializableField`-aware merge (only classes that inherit that get it).

**`JSON.parse`'s built-in reviver can't support cycles or reliable dedup, which is why `ASerializableFromJSON` doesn't use one.** `JSON.parse(text, reviver)` walks strictly bottom-up/post-order — a node's children are revived before the node itself, with no hook to revisit a node later. A `{_aserial_ref: id}` placeholder nested *inside* the very object it points back to (exactly what a genuine cycle looks like once serialized) would need to resolve before that object has been constructed at all, which a reviver-based approach cannot do. `ReviveNode`'s hand-written walk controls its own order instead (see above).

**The shell/memo scheme has one known limitation**: a one-shot static `fromJSON(data)` — which is what most classes have, via `AObject`'s inherited `CreateWithState` — builds and returns a *whole new* instance in a single call, discarding the shell that a cyclic reference may have already resolved to. So the forward edge of a cycle (A → B) resolves correctly, but the back edge (B → A) can end up pointing at A's discarded shell rather than the final object — a real, right-class instance, just not reference-equal. This doesn't crash (no stack overflow, no dangling-reference error), and a *non-cyclic* shared reference is unaffected (anything that looks the id up after the referenced object's own `fromJSON` call finishes gets the final object). `D6CycleAndDedup.test.ts` has a test that pins this behavior down.

**`GetIndexedCopy`/`ASerializableFromJSON` only dedup/cycle-protect decorated class instances, not plain objects or arrays.** A shared or self-referencing plain object reached twice via different paths is walked and copied independently each time. Shared references and cycles between decorated instances (a shared `Material`, a parent/child cycle) are handled.

**The construction-contract check (at decoration time, and again in `ValidateSerializableGraph`) has false positives.** The contract: a decorated class must be constructible with zero arguments, or provide a static `fromJSON(data)`. `constructor.length` only counts *declared* parameters before the first one with a default value or the rest (`...args`) syntax — a class declaring `constructor(x?: number)` or `constructor(x: number = 0)` reports length `0` correctly, but a class whose only required argument is supplied by every real call site via `super(...)` from a subclass, or that otherwise never gets called with zero arguments in practice, can still report a nonzero length and trigger a warning/diagnostic that doesn't reflect an actual bug. Seeing this for a class you're confident about is fine to leave, or you can silence it with an explicit static `fromJSON` (see `VertexArray2D`). The check has a false-*negative* side too: every `AObject` subclass inherits `AObject.fromJSON`, so it always passes, even if `new MyClass()` would actually throw.

**A `Date` (or other undecorated built-in with internal state) round-trips as `{}`.** Both `GetIndexedCopy` and `ReviveNode` walk a plain object via `for...in` over its own enumerable properties, which is empty for a `Date`. (Plain `JSON.stringify`/`parse` doesn't round-trip a `Date` either: it comes back as a string.)
